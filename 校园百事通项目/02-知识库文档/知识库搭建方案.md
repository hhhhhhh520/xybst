## 二、文档采集与预处理

### 2.1 采集渠道

| 渠道 | 内容类型 | 采集方式 | 频率 |
|------|----------|----------|------|
| 教务处官网 | 政策文件、通知公告 | 网页爬虫/手动下载 | 每周 |
| 学工处官网 | 学生管理文件 | 网页爬虫/手动下载 | 每周 |
| 学院官网 | 学院通知、办事指南 | 手动下载 | 每月 |
| 学校OA系统 | 内部文件 | 授权导出 | 按需 |
| 各部门咨询 | FAQ、流程说明 | 访谈整理 | 一次性 |
| 历史问答记录 | 常见问题 | 数据导出 | 一次性 |

### 2.2 文档格式标准化

**采集后的原始文档可能存在以下问题**：
- 格式混乱（PDF扫描件、图片、网页等）
- 内容重复（同一通知多渠道发布）
- 信息过时（已废止的政策）
- 结构不清晰（缺乏层次标题）

**预处理流程**：

```
原始文档
    │
    ▼
┌─────────────────────────────────────────────────────────────┐
│  1. 格式转换                                                  │
│  - PDF转文本（OCR识别扫描件）                                  │
│  - 网页转Markdown                                             │
│  - 图片内容人工录入                                            │
│  - 统一输出为Markdown格式                                      │
└─────────────────────────────────────────────────────────────┘
    │
    ▼
┌─────────────────────────────────────────────────────────────┐
│  2. 内容清洗                                                  │
│  - 去除页眉页脚、页码、水印                                    │
│  - 删除与内容无关的导航、广告                                  │
│  - 统一编码格式（UTF-8）                                       │
│  - 修正OCR识别错误                                             │
└─────────────────────────────────────────────────────────────┘
    │
    ▼
┌─────────────────────────────────────────────────────────────┐
│  3. 去重与更新                                                │
│  - 识别重复内容，保留最新版本                                  │
│  - 标记废止文件，移至历史库                                    │
│  - 添加文档元数据（来源、日期、版本）                           │
└─────────────────────────────────────────────────────────────┘
    │
    ▼
┌─────────────────────────────────────────────────────────────┐
│  4. 结构化标注                                                │
│  - 识别文档层级（一级标题、二级标题等）                         │
│  - 提取关键信息（时间、地点、条件）                             │
│  - 标记文档类型（政策/流程/通知/FAQ）                          │
│  - 添加标签（适用对象、业务领域）                               │
└─────────────────────────────────────────────────────────────┘
    │
    ▼
清洗后的标准文档
```

### 2.3 文档元数据规范

每份文档必须包含以下元数据：

```yaml
doc_id: "EDU_2024_001"           # 文档唯一标识
 title: "2024年本科生奖学金评定办法"  # 文档标题
category: "学工知识库"             # 所属知识库
subcategory: "奖学金"              # 子分类
doc_type: "政策文件"               # 文档类型：政策文件/办事流程/通知公告/FAQ
source: "学工处"                   # 来源部门
publish_date: "2024-09-01"         # 发布日期
effective_date: "2024-09-01"       # 生效日期
expiry_date: null                  # 失效日期（null表示长期有效）
version: "1.0"                     # 版本号
status: "有效"                     # 状态：有效/已废止/待更新
applicable_to:                     # 适用对象
  - "本科生"
  - "全日制"
tags:                              # 标签
  - "奖学金"
  - "国家奖学金"
  - "评定"
keywords:                          # 关键词（用于检索优化）
  - "奖学金申请"
  - "奖学金条件"
  - "奖学金时间"
related_docs:                      # 相关文档
  - "EDU_2024_002"
  - "EDU_2023_015"
```

## 三、文档分块策略

### 3.1 分块原则

**核心原则**：保持语义完整性，确保每个块包含完整的信息单元

| 原则 | 说明 | 示例 |
|------|------|------|
| 完整性 | 一个块包含完整的问答、步骤或条款 | 一问一答为一个块 |
| 适度长度 | 单块长度200-500字为宜 | 避免过长或过短 |
| 上下文保留 | 相邻块有10%-20%重叠 | 防止信息割裂 |
| 关键信息前置 | 时间、条件等放开头 | 提高检索准确率 |

### 3.2 分块策略矩阵

| 文档类型 | 分块方式 | 块大小 | 重叠 | 示例 |
|----------|----------|--------|------|------|
| FAQ问答 | 一问一答为一个块 | 不定 | 0% | Q: 奖学金怎么申请？A: ... |
| 办事流程 | 一步骤一块 | 50-100字 | 0% | 第1步：准备材料... |
| 政策条款 | 一条款一块 | 100-300字 | 10% | 第X条：... |
| 通知公告 | 整篇为一个块 | 不定 | 0% | 完整通知内容 |
| 长文档 | 按章节+滑动窗口 | 300-500字 | 20% | 章节摘要+内容 |

### 3.3 分块实现代码示例

```python
# 分块配置参数

    "default": {
        "chunk_size": 400,        # 目标token数
        "chunk_overlap": 50,      # 重叠token数
        "separators": ["\n\n", "\n", "。", "；", " "],
        "min_chunk_size": 100,
    },
    "faq": {
        "chunk_size": 1000,       # FAQ保持完整
        "chunk_overlap": 0,
        "separators": ["\nQ:", "\n问："],  # 按问题分隔
    },
    "process": {
        "chunk_size": 150,        # 流程步骤简短
        "chunk_overlap": 0,
        "separators": ["\n第", "\n步骤", "\n"],
    }
}

def chunk_document(doc, doc_type="default"):
    """
    文档分块函数

    Args:
        doc: 文档内容（字符串）
        doc_type: 文档类型，决定分块策略

    Returns:
        chunks: 分块后的文档列表
    """
    config = CHUNK_CONFIG.get(doc_type, CHUNK_CONFIG["default"])

    # 根据分隔符进行分块
    # 实际实现可使用LangChain的RecursiveCharacterTextSplitter
    # 或Coze平台内置的分块功能

    chunks = []
    # 分块逻辑...

    return chunks

def enhance_chunk(chunk, metadata):
    """
    增强分块内容，添加上下文信息

    Args:
        chunk: 原始分块内容
        metadata: 文档元数据

    Returns:
        enhanced_chunk: 增强后的分块
    """
    # 添加文档标题和上下文
    header = f"【{metadata['title']}】"

    # 添加适用对象标签
    if metadata.get('applicable_to'):
        audience = f"适用对象：{', '.join(metadata['applicable_to'])}"
        chunk = f"{header}\n{audience}\n\n{chunk}"
    else:
        chunk = f"{header}\n\n{chunk}"

    return chunk
```

## 四、向量化与索引构建

### 4.1 Embedding模型选择

| 模型 | 维度 | 优势 | 适用场景 |
|------|------|------|----------|
| BAAI/bge-large-zh-v1.5 | 1024 | 中文语义理解好，开源免费 | 推荐首选 |
| text-embedding-ada-002 | 1536 | OpenAI官方，效果稳定 | 有API预算时 |
| BAAI/bge-m3 | 1024 | 多语言支持，长文本 | 多语言场景 |

**本项目选择**：BAAI/bge-large-zh-v1.5
- 理由：中文优化好，适合校园场景；开源免费，成本低

### 4.2 向量索引配置

```yaml
# 向量数据库配置（以Coze平台为例）
vector_store:
  embedding_model: "BAAI/bge-large-zh-v1.5"
  vector_dim: 1024
  distance_metric: "cosine"      # 余弦相似度

  # 索引参数
  index_type: "hnsw"             # HNSW近似最近邻
  ef_construction: 200           # 构建时搜索范围
  m: 16                          # 每个节点的最大连接数

  # 检索参数
  ef_search: 64                  # 检索时搜索范围
```

### 4.3 混合检索配置

```yaml
# 混合检索：向量检索 + 关键词检索
retrieval:
  # 向量检索配置
  vector_search:
    top_k: 20                    # 向量检索召回数量
    similarity_threshold: 0.7    # 相似度阈值

  # 关键词检索配置
  keyword_search:
    top_k: 10                    # 关键词检索召回数量
    fields:                      # 检索字段
      - title
      - content
      - keywords
      - tags

  # 结果融合配置
  fusion:
    method: "rrf"                # RRF融合算法
    k: 60                        # RRF参数
    weights:                     # 权重配置
      vector: 0.7
      keyword: 0.3

  # 重排序配置
  rerank:
    enabled: true
    model: "BAAI/bge-reranker-large"
    top_n: 5                     # 最终返回给LLM的文档数
```

## 六、避坑方案与经验总结

### 6.1 常见问题与解决方案

| 问题现象 | 原因分析 | 解决方案 |
|----------|----------|----------|
| 检索结果不相关 | 查询与文档语义差距大 | 添加查询重写，扩展同义词；调整Embedding模型 |
| 答案遗漏关键信息 | 分块导致信息割裂 | 增加块重叠；使用更大的chunk_size；添加章节摘要 |
| 过时信息被召回 | 知识库更新不及时 | 添加时间戳过滤；优先返回最新文档；定期清理过期文档 |
| 多个相似答案冲突 | 不同文档规定不一致 | 添加来源标注；让用户判断；提示以最新为准 |
| 数学计算错误 | LLM不擅长精确计算 | 对计算类问题调用计算器工具 |
| 长文档理解困难 | 超出上下文长度 | 使用Map-Reduce策略；分段处理 |
| 专业术语理解差 | Embedding对术语编码不准 | 添加术语词典；同义词扩展 |

### 6.2 效果优化Checklist

**检索阶段优化**：
- [ ] 查询重写：扩展同义词、澄清模糊表达
- [ ] 混合检索：向量+关键词，提升召回率
- [ ] 过滤策略：按时间、适用对象过滤
- [ ] 重排序：使用专门的重排序模型

**生成阶段优化**：
- [ ] Prompt优化：添加Few-shot示例、CoT引导
- [ ] 上下文压缩：精简检索结果，保留关键信息
- [ ] 答案格式：结构化输出，便于阅读
- [ ] 引用标注：明确答案来源，增强可信度
