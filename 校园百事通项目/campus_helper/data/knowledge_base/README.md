## 知识库结构说明

知识库位于 `data/knowledge_base/` 目录下，采用**分类目录 + Markdown文档**的组织结构：

```
data/knowledge_base/
├── README.md                    # 本说明文档
├── chroma_db/                   # Chroma向量数据库存储目录
├── FAQ/                         # 常见问题解答
├── 学校概况/                    # 学校基本信息
├── 教务信息/                    # 教务相关内容
├── 图书馆服务/                  # 图书馆使用指南
├── 生活服务/                    # 校园生活服务
├── 校园服务/                    # 校园公共服务
├── 新生服务/                    # 新生入学指南
├── 奖助学金/                    # 奖励与资助信息
├── 就业创业/                    # 就业与创业服务
├── 创新创业/                    # 创新创业相关
├── 校园组织/                    # 学生组织与社团
└── 校规制度/                    # 校规校纪制度
```

### 技术架构

知识库基于 **RAG（检索增强生成）** 技术构建：

| 组件 | 技术选型 | 说明 |
|------|----------|------|
| 向量数据库 | Chroma | 持久化存储文档向量 |
| 嵌入模型 | bge-large-zh | 中文向量模型，1024维 |
| 关键词检索 | BM25 | 传统关键词匹配 |
| 结果融合 | RRF | 向量+关键词混合检索 |

## 文档分类

知识库共包含 **12个分类目录**，每个目录对应一类主题信息：

## 文档格式要求

### 统一使用 Markdown 格式

所有知识库文档必须使用 **Markdown (.md)** 格式编写。

### 推荐文档结构模板

```markdown
# 文档标题

> 一句话概述文档内容（可选）

## 一级标题

### 二级标题

内容段落...

**重点内容**：使用加粗突出关键信息。

- 列表项1
- 列表项2

| 表头1 | 表头2 |
|-------|-------|
| 内容1 | 内容2 |

> 提示信息：使用引用块展示提示或注意事项

---

（文档更新日期：YYYY年MM月）
```

### 格式要点

1. **标题层级**：
   - 一级标题 `#` 仅用于文档标题，每个文档只有一个
   - 二级标题 `##` 用于主要章节划分
   - 三级标题 `###` 用于细分章节
   - 避免超过四级标题

2. **表格格式**：
   ```markdown
   | 列1 | 列2 | 列3 |
   |-----|-----|-----|
   | 内容 | 内容 | 内容 |
   ```

3. **列表格式**：
   ```markdown
   - 无序列表项
   - 多级列表使用缩进
     - 子列表项
   ```

   ```markdown
   1. 有序列表项
   2. 第二项
   ```

4. **强调格式**：
   - 加粗：`**重要内容**`
   - 斜体：`*强调内容*`
   - 行内代码：`` `代码内容` ``

5. **引用块**：
   ```markdown
   > 提示、注意事项或引用内容
   ```

## 如何添加新文档

### 步骤一：确定分类目录

根据文档内容主题，选择合适的分类目录。参考上方 [文档分类](#文档分类) 部分。

### 步骤二：创建文档文件

在对应分类目录下创建 Markdown 文件：

```bash
# 示例：在教务信息目录下创建新文档
touch data/knowledge_base/教务信息/新文档名称.md
```

### 步骤三：编写文档内容

按照 [文档格式要求](#文档格式要求) 和 [文档内容规范](#文档内容规范) 编写内容。

### 步骤四：重新构建向量索引

添加或修改文档后，需要重新构建向量索引：

```bash
# 进入项目目录
cd campus_helper

# 运行初始化脚本（会自动加载知识库）
python -m backend.services.knowledge_base
```

或在代码中调用：

```python
from backend.services.knowledge_base import KnowledgeBaseService

kb_service = KnowledgeBaseService()
await kb_service.initialize()  # 会自动加载并索引所有文档
```

### 步骤五：验证文档检索

通过检索接口验证新文档是否被正确索引：

```python
results = await kb_service.search("新文档关键词", top_k=5)
for r in results:
    print(f"内容: {r['content'][:100]}...")
    print(f"来源: {r['metadata']['source']}")
```

## 文档命名规范

### 命名原则

1. **简洁明确**：文件名应能直观反映文档内容
2. **中文命名**：本项目使用中文文件名，便于理解和管理
3. **避免特殊字符**：不要使用 `/ \ : * ? " < > |` 等字符
4. **统一后缀**：统一使用 `.md` 后缀

### 推荐命名模式

| 类型 | 命名模式 | 示例 |
|------|----------|------|
| 指南类 | XX指南.md | 教务系统使用指南.md |
| 手册类 | XX手册.md | 宿舍生活手册.md |
| 规则类 | XX规则.md | 图书借阅规则.md |
| FAQ类 | XX常见问题FAQ.md | 学生常见问题FAQ.md |
| 信息汇总 | XX信息汇总.md | 官网信息汇总.md |
| 流程类 | XX流程.md | 请假审批流程.md |

### 命名示例对比

| 不推荐 | 推荐 | 说明 |
|--------|------|------|
| doc1.md | 教务系统使用指南.md | 明确内容主题 |
| 图书馆.md | 图书馆服务指南.md | 说明文档类型 |
| 新.doc | 新生入学指南.md | 避免单字命名 |
| 学生手册-final-v2.md | 学生手册.md | 避免版本号在文件名中 |

## 文档内容规范

### 内容质量要求

1. **准确性**：信息必须准确可靠，引用官方来源
2. **时效性**：标注信息更新日期，定期检查过期内容
3. **完整性**：主题内容完整，避免断章取义
4. **可读性**：语言简洁明了，结构层次清晰

### 内容编写规范

#### 标题规范

```markdown
# 文档主标题（与文件名呼应）

## 主要章节

### 细分章节
```

#### 联系方式规范

```markdown
## 联系方式

- **办公室电话**：(0731) 84618042
- **办公地点**：第X教学楼XXX室
- **办公时间**：周一至周五 8:00-12:00, 14:00-17:30
```

#### 流程步骤规范

```markdown
## 办理流程

### 办理步骤

1. **准备材料**：携带身份证、学生证等
2. **填写申请**：到XX办公室领取申请表
3. **提交审核**：提交材料等待审核
4. **领取结果**：3个工作日后领取
```

#### 时间地点规范

```markdown
## 服务信息

- **开放时间**：周一至周五 8:00-22:00，周末 9:00-21:00
- **服务地点**：图书馆一楼服务大厅
- **联系电话**：(0731) 84618042
```

#### 注意事项规范

```markdown
> **注意**：请在规定时间内完成办理，逾期需重新申请。

> **提示**：建议提前预约，避免排队等候。
```

### FAQ文档特殊规范

FAQ文档采用问答对格式，便于智能分块：

```markdown
# XX常见问题FAQ

> 整理自学生高频咨询问题

## 分类一

### Q1: 问题描述？

答案内容...

可以使用列表：
- 要点一
- 要点二

### Q2: 另一个问题？

答案内容...

## 分类二

### Q3: 其他问题？

答案内容...

---

> 本FAQ将持续更新，如有其他问题请咨询相关部门。
> 
> 更新日期：2026年4月
```

### 禁止内容

1. 敏感个人信息（学号、身份证号等）
2. 未授权的版权内容
3. 过时或未经核实的信息
4. 与校园服务无关的内容

## 分块策略说明

知识库采用**智能分块策略**，将长文档分割为适合检索的小块。

### 分块器类型

| 分块器 | 适用文档类型 | 分块方式 |
|--------|--------------|----------|
| MarkdownChunker | policy, guide, process | 按标题结构分块 |
| FAQChunker | faq | 按问答对分块 |

### Markdown分块策略

用于普通文档，按标题结构智能分割：

```
原文档结构：
├── # 文档标题
├── ## 章节1
│   ├── 内容段落
│   └── ### 子章节
├── ## 章节2
│   └── 内容段落

分块结果：
├── 块1: ## 章节1 + 内容
├── 块2: ### 子章节 + 内容
└── 块3: ## 章节2 + 内容
```

**参数配置**：

| 参数 | 默认值 | 说明 |
|------|--------|------|
| chunk_size | 400 | 目标块大小（字符数） |
| chunk_overlap | 50 | 块之间重叠字符数 |

**保护机制**：

- 表格完整性：不拆分表格内容
- 列表完整性：不拆分连续列表
- 标题关联：标题与所属内容保持在同一块

### FAQ分块策略

用于FAQ文档，按问答对分割：

```
原文档：
### Q1: 问题一？
答案一...

### Q2: 问题二？
答案二...

分块结果：
├── 块1: Q: 问题一？\n\nA: 答案一...
└── 块2: Q: 问题二？\n\nA: 答案二...
```

每个问答对作为独立检索单元，便于精确匹配用户问题。

### 元数据继承

每个分块继承原文档的元数据：

```python
chunk_metadata = {
    'title': '原文档标题',
    'source': '分类目录名',
    'category': '分类目录名',
    'doc_type': '文档类型',
    'file_path': '原文档路径',
    'chunk_id': '分块唯一ID',
    'chunk_index': '分块序号',
    'chunk_total': '总块数',
    'header_path': '标题路径',
    'section_title': '所属章节标题',
    'chunk_type': '分块类型'
}
```

### 分块效果示例

以"学校简介.md"为例：

```
原文档：约2000字符
分块结果：约6个块

块1：学校基本信息 + 联系方式
块2：学校简介 + 历史沿革
块3：学校荣誉
块4：学科专业 + 重点学科
块5：ESI世界学科排名 + 特色专业
块6：学位授权 + 师资力量 + 学生规模 + 科研成果
```

## 维护与更新

### 文档更新流程

1. 修改对应的 `.md` 文件
2. 在文档末尾更新日期标注
3. 重新运行知识库初始化
4. 验证检索效果

### 定期检查清单

- [ ] 检查联系方式是否变更
- [ ] 检查规章制度是否有更新
- [ ] 检查服务时间是否调整
- [ ] 移除过时内容
- [ ] 补充新增服务

### 向量数据库管理

向量数据库存储在 `chroma_db/` 目录：

```
chroma_db/
└── chroma_db/           # Chroma持久化数据
    ├── chroma.sqlite3   # 元数据数据库
    └── ...              # 向量数据文件
```

**重建索引**：删除 `chroma_db/` 目录后重新初始化即可。

## 常见问题

### Q: 添加新文档后检索不到？

A: 确保已重新运行知识库初始化，向量索引需要重建。

### Q: 检索结果不准确？

A: 检查文档内容是否清晰、标题结构是否合理、关键词是否明确。

### Q: 如何批量导入文档？

A: 将文档放入对应分类目录，运行初始化即可自动加载。

### Q: 支持哪些文件格式？

A: 目前支持 `.md`（Markdown）和 `.txt`（纯文本）格式。
